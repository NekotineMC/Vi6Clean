### Diff-scope review (cross-story)

**F1. An unattended run can stall forever, and the log never says so.** CONFIRMED mechanisms, combining ADV-2, ADV-8, ECH-1, ECH-2, ECH-3 and ECH-4:
- A brain that throws is removed for good (`Vi6Bots.java:108-114`, the Story 2.3 design), so that bot never readies again. This holds in every later lobby of the looping run (Story 4.4).
- A player who quits is dropped from the game (`Vi6PhaseGlobal.java:84-85` → `Vi6Game.removePlayer`), but nothing re-runs `checkForCompletion()`. If everyone left was already ready, and each brain readies only once per lobby or preparation (Stories 4.3 and 4.6), the phase never completes.
- A human online who never readies blocks every lobby (`Vi6PhaseLobby.java:136-142` has no timer).
- A bot in the roster's FAILED state is still listed and online but gets no tick (PLAUSIBLE, not reproduced).

`Vi6Run` has no watchdog, so in each case the last log line is either an error or nothing at all. → **fix**: have `Vi6Run` warn once when no game has ended within lobby delay + preparation + lost timer + a margin, naming the phase and the unready players; and re-run the current phase's completion check when a player leaves. Upstream lesson: P1.

**F2. The humans-online paths of `/bot run` were never exercised.** Story 4.4 left them to the dev server: "check them on the dev server in Story 4.6" (`deferred-work.md:152-153`, `spec-4-4…md:77,90`). Story 4.6's ACs require no human online, and its note lists only bot-only runs, without mentioning the gap (`dev-server-check-4-6.md:11,33-37`). The humans-kept path, the `6 - humans` count, the no-room refusal and the partial-spawn rollback remain unverified, while the deferred entry still points at a done story. Found by the retro and by VG-5. → **fix** (dev-server check with one human) and retarget the deferred entry. Upstream lesson: P1.

**F3. Run-summary and brain regressions that no test would catch.** CONFIRMED by grep (VG-1, VG-2, VG-3, VG-4):
- No test re-reads a bot's lobby ready state after it first readies, so dropping `readied = true` (`LobbyBrain.java:64-66`) would flip `/game ready` every tick and stay green.
- No test checks the `duration=` value, or that it resets per game (`Vi6Run.java:90-91`).
- No test has a run active when an artefact ends `lost`, so `stolen` (`s < 3`, `Vi6Run.java:80`) could stop counting lost artefacts unseen.
- No test checks that `/bot run` keeps the forced-KoTH override that the soak test relies on (`Vi6GameReset.clearBots`).

→ **fix**, as one test-hardening item, folded together with Epic 3 item 5 (still open).

**F4. A `Vi6BotCommandsIT` assertion became vacuous in Story 4.6.** `Vi6BotCommandsIT.java:74-76` asserts that the lobby stays because Bot_1 has no brain. Under the 10 s default delay that Story 4.6 introduced, the other bots are not ready yet either, so the assertion holds whatever Bot_1 does (ECH-7/8, CONFIRMED: the class calls no `shortLobbyReadyDelay()`). Story 4.6's commit message says "ITs use a 1 s delay", which is true only for the classes that call the hook. → **fix** (in the F3 item).

**F5. Seed replay with KoTHs on:** see A5. → **fix**: say in the `Run démarré` message and the pending operator documentation (`deferred-work.md:155`) that the seed replays bot picks only, or seed KoTH selection from the run. Optionally add `seed=` to each `Game ended` line (ADV-12).

**F6. A failing `logRoundResult` skips `Vi6RoundEndEvent`.** The event fires as the last statement of the guarded log step (`Vi6PhaseInfiltration.java:237-248`). If building the scores throws, `logThenComplete` logs a WARN, `complete()` runs, and `Vi6Run` silently skips the game, so later `game=N` numbers and the next `duration` are off (ADV-3, ECH-5; mechanism CONFIRMED, trigger hypothetical). → **defer**.

**F7. Every game of a run may give the same bots the same roles.** `LobbyBrain.pickTeam` breaks ties toward GUARD in roster order (`LobbyBrain.java:80-103`). The lobby's thief/guard swap may then be undone each game, so runs would never play a former thief as a guard (ADV-4, PLAUSIBLE: picks depend on the post-swap teams of bots that have not picked yet, and the 4.6 note did not log roles). → **defer**: settle it by logging each game's teams in a looping IT.

**F8. The soak test covers neither KoTHs nor the production lobby window, and its replay check is within one boot.** `shortTimersWithoutKoths()` disables KoTHs and shortens the lobby delay (`Vi6TestHooks.java:260-270`). `FIRST_PICKS` is static, so "same seed, same picks" is checked only inside one JVM, and it compares the brain's *requested* entrance, not the selected spawn (`Vi6SoakIT.java:97,278-317`) (ADV-5, ADV-6, ADV-7). The determinism ACs are about one boot, and Story 4.6 covered KoTHs and real timers on the dev server. *Accept* the scope; **defer** reading the selected spawn instead of the brain's pick (cheap, and it catches `/game entrance` silently failing).

**F9. Two "is thief" predicates:** see A2 (ADV-10). → **defer**.

**F10. `/game team` and `/game lobby` are unguarded:** see A4 (ADV-11). → **defer**.
