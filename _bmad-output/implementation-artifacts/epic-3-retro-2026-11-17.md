### Diff-scope review (cross-story)

**F1. Duration values are unvalidated after the 3.1 rework** — `InfiltrationPhaseConfig.java:24-55`, `PreparationPhaseConfig.java:19-25`. The setters and `config.yml` accept 0, negatives, NaN, `.inf` and sub-tick values. Below 0.05 s, `Tick.fromDuration` gives 0 ticks. With 0 preparation ticks, `Vi6PhasePreparation.onTick` (`:291-298`) calls `complete()` and then, on a second boundary, `bossbar.progress(1/0f)`, an out-of-range value. A huge value overflows `toIntExact` in a phase field initializer, so the phase is never built. Applies to humans too, since 3.1 made fractional values legal in `config.yml`. (ADV-1, ECH-3/4; mechanism CONFIRMED, outcome PLAUSIBLE) → **fix**: validate in setters and on load (≥ 1 tick, finite, ≤ int ticks), and correct the 3.1 triage log.

**F2. A bad forced-KoTH override desyncs the phase machine's index** — `Vi6PhaseInMap.java:114-117` + NekotineCore `PhaseMachine.java:136-145`. `onPhaseComplete` runs `++currentPhaseIndex` before `goTo`. If the lobby completes (humans `/game ready`) while the override is bad, the constructor throws and the lobby stays up, but the index has already advanced. The next start skips a phase. The 3.2 commit's claim that "a bad override leaves the lobby intact" is true only for `goTo` driven directly, which is all the IT does. Reachable through F3. (ECH-1 + claim 1; index-advance CONFIRMED, skip outcome PLAUSIBLE) → **defer** to NekotineCore (same root as the deferred "wedged PhaseMachine" entry), plus F3's guard on the Vi6 side.

**F3. The forced-KoTH override and in-memory durations are sticky and silent** — `Vi6Game.java:351`, `setMapName` at `:226`. The override lasts until reset; `setMapName` doesn't revalidate or clear it, and nothing logs that a test override is active (the 3.1 #8 warning went with the module). If a run aborts before reset, the next human round plays with test KoTHs and timers. After a map change, every start throws (feeding F2). (ADV-10, ECH-2, CONFIRMED by reading) → **fix before Story 4.4**: clear or validate in `setMapName`, and log a warning when a phase is built with an override active.

**F4. The death-delay task outlives its round** — `InMapPhasePlayerWrapper.java:274-291`. The 3 s DEAD `BukkitRunnable` is never stored or cancelled; `tearDown` (`:125-140`) cancels only the escape and capture tasks. Pre-existing, but Epic 3 made it reachable: a `Vi6GameReset` or round end inside 3 s of a thief death leaves the task to call `thiefObjectiveLost` on the old phase and `checkForCompletion` on whichever infiltration is current, which is the next round in Story 4.4's back-to-back runs. (ADV-3, ECH-6, CONFIRMED) → **fix before 4.4**.

**F5. The round-result line can report a dead thief's artefact as `stolen` on short timers** — `Vi6PhaseInfiltration.java:163-174`. The 3.4 triage #2 fix logs after end-spectator time, assuming 5 s > 3 s death delay. The tests (and Story 4.4) use 0.5 s. (ADV-2, ECH-5, CONFIRMED by reading) → **fix with F4** (complete after `max(endSpectator, pending deaths)`), and fold it into the existing deferred "assert `stolen`/`lost`" item.

**F6. `logRoundResult` can block `complete()`** — `Vi6PhaseInfiltration.java:166-170`. A diagnostic line runs unguarded before `complete()`. Any exception leaves the round stuck in end-of-game spectator mode. (ADV-4, ECH-11, CONFIRMED) → **fix**: try/catch or `finally`.

**F7. The result line is not yet a contract Story 4.4 can parse** — `Vi6PhaseInfiltration.java:181-187`. It is not logged when a round ends by reset, `goTo` or disable (ADV-6). `all-thieves-left` is vacuously true with an empty thief team (ADV-7). Artefact names are unescaped (ADV-5). (CONFIRMED by reading) → **defer to Story 4.4**, which owns the line's winner and duration extension; add to its spec.

**F8. The capture and escape delays are only checked from above** — `Vi6PhaseMachineBotIT.java:219,251,265`. The test waits for the gates to open but never asserts they were closed first, so a delay that is never applied passes. `durationsKeepFractionsOfASecond` doesn't cover these two fields. (VG-1, CONFIRMED) → **fix** (small test change) and close the 3.1 `deferred-work.md` entry.

**F9. Wait messages round fractional delays down** — `InMapPhasePlayerWrapper.java:191,206` use `Duration.toSeconds()`, so 0.5 s reads "0s". (VG-2, CONFIRMED) → **defer** (cosmetic; production config uses whole seconds).

**F10. `Vi6GameReset` is not yet safe with humans online** — `Vi6GameReset.java:38-52`.
- It aborts a running human round without notice, and removes every roster bot, including ones a human added (ADV-8).
- Removing bots before `goTo(Lobby)` can briefly show humans "La partie est finie" (ECH-9).
- `tryLoad()` swaps the whole live config from disk: a YAML typo means defaults (ADV-9, ECH-10).
- Called from inside a roster tick, removal only queues (ECH-7/8).

(Reading CONFIRMED; tick-reentry PLAUSIBLE) → **defer to Story 4.4**: its spec must say whether the run command refuses while a human round is live, and whether to restore a duration snapshot instead of `tryLoad()`. Together with the A5 "empty teams" question.

**F11. A stale wrong comment** — `Vi6TestHooksIT.java:63,131,210,263`: "Assertion errors inside onMain only reach the log". Story 3.3 triage #3 proved this wrong and removed it from `PortableTeleporterBotIT` only. (ADV-11, CONFIRMED) → **fix** (delete).

**F12. The `int`→`double` change may rewrite server `config.yml` as `300.0`** — `InfiltrationPhaseConfig.java:12-24`, if Configurate serializes the doubles on save or `override-config`. Not observed: `test-bundle` config still shows `300`. (ADV-14, PLAUSIBLE) → **accept**; check once on the dev server.

Dropped as not holding against the source: none outright. ECH-3's "preparation bossbar progress(n/0) throws" is narrowed in F1 (`complete()` runs first; the throw needs the 0-tick tick to land on a second boundary).

### Process lessons (from spec change and triage logs; no session logs)

- **P1. A rework silently drops earlier review patches.** The 3.1 rework kept the triage rows but deleted the code that implemented them (F1). Lesson: when a human-ordered rework replaces code, re-triage the triage log in the same PR.
- **P2. Cross-story knowledge didn't flow back.** 3.3 found the `onMain` comment wrong but fixed one file (F11); 3.4 covered 3.1's deferral but didn't close it (A5, F8); each story re-wrote its helpers (A2). Lesson: the story's done-step should grep for the pattern it just corrected and check `deferred-work.md` entries naming its story.
- **P3. Fixes reasoned on defaults break under the epic's own short timers.** 3.4 #2 relies on the 5 s default, but the epic's whole point is shortened timers (F5). Lesson: triage of timing fixes must state the timer assumption and check it against the test values.
